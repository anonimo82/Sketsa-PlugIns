M5 FIX-ONLY NOTE — 1.6.6
------------------------
GLOBAL pivot correction to existing Test A.

Editor-created transforms now use the object's local visual center as the
default pivot:
- rotate: standard rotate(angle cx cy)
- scale: standard SMIL helper translate(+pivot), scale, translate(-pivot)
- skewX: standard SMIL helper translate(+pivot), skewX, translate(-pivot)
- skewY: standard SMIL helper translate(+pivot), skewY, translate(-pivot)

The helper animateTransform nodes are standard SVG/SMIL, hidden from the
timeline, synchronized with the main track timing, and deleted together with
the main track. This keeps save/reopen behavior portable.

Translate is unchanged because translation has no pivot.

No new test case has been added.

M5 FIX-ONLY NOTE — 1.6.9
------------------------
Motion Anchor is now configurable in the existing Test H:

- Center: editor-friendly default for newly-authored Motion tracks.
- Local origin: anchors local (0,0) to the motion path.
- Custom: anchors the supplied local X/Y point.
- SVG native: no Sketsa anchor compensation.

IMPORT FALLBACK:
If an imported SVG animateMotion has no data-sketsa-motion-anchor metadata,
Animation Editor automatically uses SVG native semantics. Existing external
SVG files are therefore not silently converted to center-anchor behavior.

No new test case has been added.


M5 FIX-ONLY NOTE — 1.6.10
-------------------------
Motion anchor compatibility correction.

"SVG native" is now explicitly "SVG native (import)" and is treated as an
IMPORT FALLBACK, not as a normal authoring anchor mode.

- Newly-created editor Motion tracks default to Center.
- Editor-authored tracks should use Center, Local origin, or Custom.
- Imported/unmarked animateMotion keeps native SVG behavior automatically.
- Applying inspector changes to an imported/native track does NOT add Sketsa
  anchor metadata unless the user explicitly chooses Center/Local origin/Custom.
- An editor-authored track cannot be switched to the import-only native mode,
  avoiding the static-transform double-placement case seen in Test H.

No new test case has been added.


M5 FIX-ONLY NOTE — 1.6.11
-------------------------
Correction to existing Test I / multi-object authoring.

Tracks created by ONE Add Track operation on multiple selected objects are now
linked with a persistent data-sketsa-multi-edit-group identifier.

Editing the selected linked track propagates the SAME authoring changes to all
tracks created by that multi-object operation:
- duration / timing / fill / calc / additive / accumulate;
- keyframe values and key times;
- Add Keyframe / Delete Keyframe;
- Set values;
- Motion authoring fields.

The edit remains ONE native Sketsa Undo transaction.

Deleting a track is intentionally NOT propagated: deleting the track from one
object affects only that object, as required by Test I.

After the multi-object Add Track operation the document-wide runtime is also
re-evaluated immediately so all linked objects preview at the same time.

No new test case has been added.
